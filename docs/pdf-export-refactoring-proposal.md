建议把项目从“DOM 截图分页 Demo”推进为“有明确支持范围、失败策略和质量评估的财务单据导出组件”。保留 React、TypeScript、html2canvas、jsPDF，优先修复导出链路，再建立分页模型、按页渲染、任务管理和评估集。

## 3. 业务场景如何扩展

扩展应围绕财务单据的真实约束，而非堆砌名词。以下是拟建演示与验收场景，不声称已在原公司全部落地。

| 场景 | 文档内容 | 核心约束 |
| --- | --- | --- |
| 付款凭证 | 单据抬头、往来单位、费用明细、审批意见、签章 | 金额与审批内容完整；签章不能缺失后仍报告成功 |
| 供应商月度对账单 | 分组明细、长备注、小计、总计 | 明细不漏不重；表头重复；合计区合理跟随 |
| 报销申请单 | 多段中文、嵌套卡片、附件缩略图、审批流 | 长文本按行断开；普通卡片整体换页；资源加载可检测 |
| 横向财务报表 | 多列表格、双层表头、长编号 | 明确列宽；过宽内容有可读性约束，不能无限缩小 |
| 连续多单据导出 | 多张凭证合成一个 PDF | 新单据强制另页；编号和模板一致；共享同一数据版本 |

建议 V1 支持：水平书写的普通文档流、基础富文本、普通表格、无跨页 rowspan 的复杂表头、图片、签章、页眉页脚、A4/A3/自定义横竖向配置。

V1 明确限制：虚拟列表必须由业务提供完整数据并构造打印视图；不直接导出未挂载的数据；跨页 rowspan、任意绝对定位、竖排文字、复杂变换、交互视频等先拒绝或要求专用模板。嵌套表格等能力必须通过专项样例后再开放。

| 路线 | 适合 | 代价与边界 | 本次选择 |

## 5. 模块设计

| 模块 | 输入 → 输出 | 负责事项 |
| --- | --- | --- |
| 业务打印适配器 | 业务快照 → 打印 DOM、节点标记、关键资源清单 | 固定数据版本；移除交互控件；提供完整表格数据 |
| prepare | 打印 DOM＋配置 → 稳定快照 | 固定宽度的隔离 iframe；样式和字体；图像解码；业务就绪；禁动画 |
| measure | 稳定快照 → LayoutDocument | 根相对坐标、文本行片段、行高、分组、资源与布局限制 |
| paginate | LayoutDocument＋PageSpec → PagePlan | 纯函数分页，记录每个断点的原因和节点归属 |
| render | PagePlan → 单页图片 | 按页组装 DOM，确认未重排，逐页截图和释放临时资源 |
| compose | 单页图片＋页眉页脚 → Blob | PDF 页面尺寸、图像放置、页码、总页数和文件输出 |
| task / diagnostics | 全流程 → 状态、错误、耗时 | 并发、取消、超时、有限重试、清理和诊断 |
| evaluation | 固定样例＋产物 → 评估报告 | 完整性、断点、视觉、性能与故障恢复验证 |

目录建议：业务演示放 `src/pdf-demo`；复用组件放 `src/pdf-export/{prepare,measure,paginate,render,compose,task}`；回归样例及脚本放 `evaluation`。开发预览读取相同 PagePlan，不能再维护一份不同规则的分页算法。

## 6. 分页算法

### 6.1 坐标和页面预算

测量统一使用打印快照中的 CSS px；PDF 组合统一使用 pt；Canvas 像素仅用于渲染，不能混入断点计算。

```text
relativeTopPx = nodeRect.top - printRootRect.top
ptPerCssPx = contentWidthPt / printRootWidthPx
contentHeightPt = pageHeightPt - marginTopPt - marginBottomPt
                  - headerHeightPt - footerHeightPt - headerGapPt - footerGapPt
contentHeightPx = contentHeightPt / ptPerCssPx
```

先校验所有值为有限正数。空内容、宽度为零、页眉页脚占满页面、页边距不合法，全部在渲染前失败。PDF 实例实际宽高为最终依据，不重复硬编码 A4 尺寸。

### 6.2 内容语义

业务通过 `data-print-keep-together`、`data-print-keep-with-next`、`data-print-break-before`、`data-print-repeat-header` 标记规则。原生 TR、P、标题等有默认适配器，第三方 UI 类名不是通用算法协议。

| 内容类型 | 正常情况 | 高于一页时 |
| --- | --- | --- |
| 普通表格行 | 整行放不下则移到下一页 | V1 默认报错；可选模板明确支持单元格按行同步拆分后再开放 |
| 段落、长备注 | 能放下则整体放；长段落选择合法行间断点 | 逐行分配；保留完整文本片段和顺序 |
| 卡片、签章、图片 | 默认整块换页 | 图片在最小可读比例内缩放；其余按显式规则拆分或报错 |
| 标题＋正文 | 标题至少跟随下一块的首段或规定行数 | 不可满足时给出规则冲突，不能反复空翻页 |
| 小计、合计 | 尽量与关联明细跟随，数据只出现一次 | 超出预算按模板约定独立成块，不自行改金额或合并业务数据 |

长文本采用 Range.getClientRects 获取文本片段的实际矩形；按 y 位置、重叠关系与容差聚合视觉行。一个矩形并不必然等于一整行，混合字号、内联 span、链接和强调文本需要专项处理。仅对候选断点附近细分文本偏移，避免逐字符扫描整篇长文。不得仅凭 getComputedStyle().lineHeight 或固定步长猜测全部行。

规划器使用显式循环：尝试放入 → 选择规则允许的断点 → 输出页面片段 → 游标推进。每次必须消费内容或结束任务；若不可推进，抛出分页错误，禁止死循环。文本偏移使用可验证的片段范围，处理 Unicode 与字素边界，避免截开组合字符。

### 6.3 分页不变量

- 每个正文内容片段恰好出现一次，保持原顺序；页眉、页脚、表头等重复装饰单独标记。
- 页内内容不侵入页眉页脚；断点严格推进，无重复页或意外空白页。
- 内容起点到终点全部有归属；不能靠“后续有另一个 DOM 节点”才补出最后几页。
- keep-together 只在块本身能装下一页时强制，超高块走明确策略。
- 相同快照、配置及排版环境产出相同 PagePlan。
- 文本孤行控制以可配置最少行数约束，默认候选值为页首/页尾各至少 2 行；规则冲突必须有降级顺序。

## 7. 长文档和资源预算

当前画布原始 RGBA 数据的量级约为 `width × height × scale² × 4 bytes`。例如 1200×50000 CSS px、scale=4，单份像素约 3.58 GiB；这只是理论量级，不是本次测得的峰值，浏览器可能在分配前已经拒绝。编码、克隆和 PDF 对象还会增加资源占用。

重构方向是“先规划页面，再组装和渲染单页”，不再先创建整篇 Canvas：

1. 在固定打印宽度下测量完整打印快照，生成 PagePlan。
2. 按计划复制该页所需的块或文本范围，保留必要祖先样式、表格列宽及重复表头。
3. 单页组装后复核高度与关键边界；复制改变选择器、列宽、计数器或段落边距时，先修复适配器，不直接截图错误布局。布局校正必须限定次数。
4. 同时仅渲染一页，加入 PDF 后释放该页 Canvas、临时 DOM 和 URL；重复静态页眉页脚可复用。
5. 像素预算决定 scale 上限，不盲从设备 DPR；低于最小可读清晰度则拒绝并提示拆分或更换模板。

不能把“对整根 DOM 多次设置 x/y/height 裁剪”描述成完整性能解决方案：即使画布缩小，每页仍可能重新克隆、解析整篇 DOM，成本接近页数乘节点数。按页组装需用基准验证；完整测量 DOM 和最终 PDF 缓冲仍随文档大小增长，因此总内存不是常数。

对 maxPages、节点数、资源数、预估像素和输出体积设预算，并在 compose 阶段检查实际输出。超限在分配大资源前尽量拒绝；具体上限由目标浏览器和设备评估决定。若需要海量报表、可搜索正文或批处理，另立服务端/结构化 PDF 路线。

## 8. 错误处理与可靠性

任务状态：idle、preparing、measuring、paginating、rendering、composing、completed、failed、cancelled。前端展示当前阶段、已完成页数和可执行提示；百分比只在有真实分母时展示。

| 错误类型 | 处理策略 |
| --- | --- |
| INVALID_SOURCE / INVALID_CONFIG | 明确失败；保留可读 message，不静默成功 |
| RESOURCE_LOAD_FAILED | 附关键资源标识；图片重试至多 1 次；签章、条码、必要字体等未满足要求则终止 |
| OPTIONAL_RESOURCE_MISSING | 按配置显示占位并返回 warning；不得将有警告产物描述为完全通过 |
| LAYOUT_UNSUPPORTED / BLOCK_TOO_LARGE | 指出不支持的节点规则；要求拆分或专用模板，不自动删内容 |
| LIMIT_EXCEEDED / CANVAS_RENDER_FAILED | 预算内可降低 scale 重试 1 次；改变清晰度必须反馈；仍失败则终止 |
| TIMEOUT / CANCELLED | 停止后续页，禁止旧任务完成后触发下载，清理独立快照和临时资源 |
| PDF_COMPOSE_FAILED | 丢弃不完整输出并保留脱敏诊断；不得下载半成品 |

重试受任务总时限约束；配置错误、版式不支持不重试。重试必须使用同一业务快照，不能在重试期间抓取已变化的数据。

一个文档默认一个活动任务，其他请求明确拒绝或排队；任务 ID 防止旧结果覆盖新结果。React loading 只是界面反馈，任务层仍需保护。所有出口均在 finally 清理临时节点、Canvas、对象 URL 和事件监听；外层逻辑取消后，还要处理尚未返回的渲染调用。

AbortSignal 与 Promise.race 不能强制中断 html2canvas 或长同步计算。V1 在阶段/页之间协作取消，进行中的调用结束后丢弃结果；主线程分批让出执行权。若后续要求硬中断，需采用可销毁的执行上下文或更换引擎，单独验证内存释放；不承诺即时取消。

诊断记录 taskId、模板版本、引擎版本、页数、阶段耗时、失败页码、错误码、重试与清晰度调整。默认不上传财务正文、金额、姓名、图片或完整 DOM；开发模式下的 PagePlan 可供本地排查。

“生成完成”以得到合法 Blob 和通过产物检查为准；触发下载不等于已确认用户磁盘成功写入，两种状态不能混同。

## 9. Evaluation：建立可复现的质量评估

这是确定性导出系统，优先使用规则、产物检查和视觉对照，无需为了名词增加 LLM 打分。

### 9.1 样本与分层

首轮计划建立至少 40 个手工审核样例，含基础财务单据、极端布局、故障注入和环境变化；再生成断点附近的参数样本。每份样例包含输入数据、样式/字体、关键节点 ID、预期规则、允许断点、业务内容清单、预期成功/拒绝状态和人工确认的参考页面。

样例必须覆盖：

- 短/长中文、英文、混排、不同字号行高、嵌套 span、长编号、空段落、连续空白。
- 刚好装满、差 1px、超 1px、多个连续换页、单段超过一页、单行/卡片超过一页。
- 100/1000/5000 行阶梯数据，1/10/30/50 页文档；超过准入预算的样例验收“正确拒绝”，不混入导出成功分母。
- 单独页眉、单独页脚、同时存在且高度不同、动态 n/N 页码、重复表头、合计区。
- 签章慢加载、资源 404、CORS 拒绝、字体失败、连续点击、取消后重试、切 Tab/卸载。
- 横竖向、自定义尺寸、不同打印宽度、DPR 1/2/3、页面滚动位置、目标 Chromium/Firefox/WebKit 环境。

| 层次 | 验证对象 | 方法 |
| --- | --- | --- |
| 类型/契约 | 选项、单位、资源与错误结构 | TypeScript＋输入校验 |
| 算法 | PagePlan 与所有不变量 | 纯函数单测、生成边界数据、失败输入 |
| 真实排版 | 字体、文本行矩形、表格与资源时序 | Playwright 在真实浏览器执行；jsdom 不承担几何正确性验证 |
| PDF 产物 | 页数、纸张尺寸、关键内容、边界与视觉 | 获取 Blob，解析页面元数据，将实际 PDF 每页栅格化，与人工参考比对 |
| 性能/可靠性 | 各阶段耗时、资源、取消、连续导出 | 固定环境重复采样、故障注入与压力测试 |

截图比较必须包含最终 PDF，不能只比较网页预览。PDF 正文为图片时不能只靠文本提取查漏；PagePlan 记录内容归属，最终页面通过关键区域图像匹配和人工审核交叉验证。OCR 可以辅助找缺失，但不得作为财务内容正确性的唯一证据。

原始截图基准先由人工审核，不能直接把旧版本错误产物批准为正确基准。固定浏览器、系统、字体和依赖版本；每个目标浏览器有单独基准。时间戳等动态区域用固定测试值，不屏蔽金额、表格边界或正文。

### 9.2 指标定义与拟定门槛

| 指标 | 定义 | 首轮发布门槛 |
| --- | --- | --- |
| 关键业务内容完整性 | 明细 ID、金额、签章等在计划中覆盖且产物中可确认，无漏重 | 手工审核核心样例 100% 通过 |
| 分页规则通过率 | 每个样例的允许断点、不可拆块、表头、页眉页脚断言 | 支持范围内核心样例全部通过 |
| 导出成功率 | 有效且在预算内请求获得有效 Blob 的比例 | 回归样例全部通过；线上目标待有真实样本再制定 |
| 预期拒绝正确率 | 超限/不支持/关键资源失败时符合预期地终止 | 故障集全部通过；与正常导出成功率分开统计 |
| 视觉差异 | 固定环境下的页图差异、关键区域差异及人工审核 | 阈值先据字体抗锯齿噪声校准；关键区域不接受语义缺失 |
| 性能 | 准备/测量/分页/渲染/组合的中位数、P95、总耗时与文件大小 | 先记录基线，再以目标设备的实测设置预算 |
| 稳定性 | 连续任务后的残留 DOM/URL/Canvas、可观察内存趋势、UI 响应 | 连续 20 次导出＋取消/失败样例无残留任务和持续资源增长迹象 |

每个性能档位建议先预热 3 次、采样至少 30 次；记录设备、浏览器、DPR、字体、文档节点数、图片量和冷热缓存条件。30 次 P95 仅作为初步估计。浏览器 JS heap 不等于 Canvas/浏览器总内存；不同环境使用可用的堆、进程及资源计数观测，说明测量范围。

有条件时，用同一输入对比“原实现、修复后的整页方案、按页方案”，报告成功率、P95 耗时、可观察峰值资源和体积。旧实现失败时，记录失败原因，不把成功请求的短耗时当成性能优势。

建议命令契约为 `test:unit`、`test:e2e`、`eval:pdf`、`eval:perf`。评估结果包含 JSON 指标和可阅读报告，失败时保留脱敏样例、PagePlan、期望/实际页图与差异图。上述命令、样例和报告系统均待实现。

## 10. 实施顺序与验收

| 阶段 | 工作 | 完成条件 |
| --- | --- | --- |
| M0：基线和正确性 | 导出/调试分离；修复页眉页脚、尾部分页、行识别；移除危险段落递归；校验与错误提示；修复失效测试 | 页面真实生成 PDF；历史缺陷都有回归样例；未经支持的长段落先明确拒绝 |
| M1：分页模型 | 打印快照、单位模型、块标记、行测量、纯分页器、重复表头、PagePlan 预览 | 长文本和核心单据满足不变量；预览与最终分页一致 |
| M2：可靠性与长文档 | 按页 DOM 渲染、预算、进度、任务互斥、协作取消、有限重试及清理 | 慢资源/失败/取消可恢复；规模梯度有基准和准入上限 |
| M3：评估与交付 | 完整评估集、PDF 产物对比、性能报告、CI、接入文档和示例模板 | 核心样例通过；失败产物可定位；新页面按协议接入 |

先锁定当前依赖版本建立基线，依赖升级另做风险审查与兼容验证，避免把引擎变化与算法重构混为一次实验。迁移期间保留旧 API 适配层，新旧路径均可对同一样例输出比较；有真实业务接入后再按模板逐步切换。

V1 不新增数据库、任务服务或模型调用。真正需要超大文档后台生成时，再用已有引擎边界接入服务端方案。

## 11. 文章与面试材料如何组织

建议标题：**《从截图分页到可靠导出：复杂财务单据 PDF 方案重构》**。

文章按“业务约束 → 旧实现与可复现问题 → 技术取舍 → 分页和资源设计 → 失败处理 → 评估结果 → 支持边界”展开。算法只承担其中一部分，重点解释如何确保文档完整、错误可见、资源可控，以及如何证明改进。

2023 年项目与本次重构分开写：历史业务与推广成果来自真实工作；长文本、预算、故障注入和评估体系在完成后以“后续开源重构”描述。避免“完美解决”“全场景兼容”“显著提升”而没有验收口径。

待补量化证据：

- 历史接入页面数/模板数、团队使用范围、接入一次所需时间；明确数量来自日志、清单还是回忆估算。
- 重构样例数、浏览器环境数、覆盖业务单据类型数、历史缺陷回归结果。
- 在指定设备和文档规模下的成功率、P95、文件体积、资源测量范围及前后差异。
- 社区文章地址和阅读/赞藏统计日期；不要直接把技术社区指标等同于生产可靠性。
