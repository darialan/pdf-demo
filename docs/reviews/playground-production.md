# Playground 生产验收记录

范围：四个演示场景、设置、页面标记、纸张预览、PDF 导出，以及它们共用的 DOM 快照、资源等待、测量和分页实现。该功能在浏览器本地运行，没有独立后端服务；本次不引入服务端上传、存储或渲染。

## 产品与交互约定

- 顶部四个 tab 选择内容类型；下方显示的内容是打印输入。排除内容通过 `ignore` 规则处理。
- 长表格展示连续行分页；长文章展示按文字行分页；复杂图文保留原文的公式、代码和图片样式；页眉页脚展示跨页重复的品牌信息。
- “检查分页”包含独立的页面标记和纸张预览。一部分失败时保留另一部分，分别提供重试。
- 检查不是导出的前置条件。加载失败时不能导出半篇文章，必须能够原地重试。
- 关闭预览后可以重新打开；退出检查、切换 tab、内容改变、尺寸改变和卸载会使旧结果失效并取消等待。
- 导出显示实际页进度，可取消；失败保留可操作的错误和重试入口；完成、失败、取消均清理临时 DOM 和画布。
- 检查协议统一使用 `atomic`、`splittable`、`ignore`、`page-break`。操作和错误提示使用中文。

## 已修复的审查发现

| 问题 | 改动与验证方式 |
| --- | --- |
| 预览与导出独立计算布局，页眉间距、页脚定位、顶部页码可能不一致 | 使用同一 `prepareLayout` 快照、分页器和页面几何；预览序列化已测量的快照，不再重新克隆源页面 |
| 忽略选择器仅跳过测量，没有移除对应快照内容；高度相减不能模拟 grid/flex 与 margin collapse | 在快照排版前按生效规则移除整个子树；测量始终使用当前 DOM 自己的坐标；真实浏览器覆盖 grid 与失效图片的 ignore |
| `atomic` 配置错误降级为拆分 | 显式 atomic 超高报出区域名称；只有 table row、keepOrSplit 等明确的可降级规则深入测量 |
| 混排保护区间被反复扫描 | 先排序合并重叠区间，再单向扫描分页；用随机小数布局检验连续覆盖与不穿过保护区间，并覆盖 50,000 个区间 |
| 预览与导出争用同一源区域，旧任务仍持有快照 | 预览任务具备 AbortSignal 和代次检查；导出开始前取消并等待旧预览释放 |
| 预览复制源 ID，重复文档与 SVG 引用有冲突风险 | 每个预览页独立 ID 命名空间，同步改写 label、aria 和 SVG paint/href 引用 |
| Ant Tabs 延迟挂载后就绪状态可能不再更新 | 观察工作台的内容挂载和 data-print-status，加载失败时禁用打印，保留原地重试 |
| HTML 序列化丢失实时表单值与 canvas 内容 | 保留 input、select、textarea 状态；canvas 转换为图片；移除复制内容的事件属性和 autofocus |
| 全屏预览无键盘焦点约束，窄屏会横向溢出 | 预览按钮具有名称；全屏使用 dialog 语义和焦点循环，Esc 返回原焦点；按实际视口计算缩放 |
| 预览滚动后不断保留整篇文档副本 | 前两页即时挂载，其他页只在滚入附近时挂载，滚远后释放 |
| 资源等待在后台 tab 可能被 rAF 无限挂起，慢图片可能冻结为 0 高度 | 资源等待与布局等待统一置于超时/取消保护内，移除无限 rAF 依赖；先等待源图片加载，再冻结计算样式，并用延迟加载的真实图片做回归 |
| 失败路径可能遗漏清理 | 捕获器初始化、截图、序列化、资源失败与取消均有清理回归测试 |
| 内置 PDF 字体不支持中文页码 | 中文页码使用浏览器字体生成小型透明位图，避免乱码；数字页码保留 PDF 文本 |
| 每页截图重复克隆原页面与所有预览副本，复杂图文导出约 99 秒 | 只克隆当前打印快照、祖先和 head 资源；同一份 12 页文档实测导出约 30 秒 |
| PDF 依赖版本陈旧 | 升级 jsPDF；实际导出与 PDF 解析覆盖其兼容性 |

## 验收命令

```sh
npm ci
npx playwright install --with-deps chromium
npm run check
```

`npm run check` 依次运行 TypeScript、单元/组件测试、库构建、前端生产构建及 Playwright。前端生产构建不再强制关闭 CI 的警告检查。

浏览器测试由两个本地测试服务提供：4173 端口加载生产构建，4174 端口只加载测试夹具与分页源码。测试夹具不包含在生产输出中。开发环境的 HTTP 代理不会代理这两个本地地址。

自动化测试包括：四个场景真实下载 PDF，解析每页的纸张尺寸、页码和图像内容，比较预览页数；检查前后源文档几何一致；失败后重试；关闭与切换期间的取消；390px/768px 窄屏；全屏键盘退出；错误设置保护；grid ignore；超高 atomic；中文页码与声明式页眉页脚。

CI 配置位于 `.github/workflows/quality.yml`，失败保留浏览器截图、trace 与报告。

## 明确的支持边界

- HTML 预览使用浏览器 DOM，PDF 使用 html2canvas 光栅化，因此 PDF 正文不是可搜索的矢量文字；不能把此实现称为对任意 CSS、Shadow DOM、跨域 iframe 或视频的无条件完整还原。
- 图片必须成功加载且可用于 canvas；跨域图片需要相应 CORS。不可读画布或资源失败应明确报错，不生成缺失内容的 PDF。
- 默认限制 100 页、200,000px 高度、200,000 个参与测量的文本字符；超出限制说明原因。逐页 canvas 有像素预算，不分配整篇长画布。
- 显式 atomic 无法放入一页时必须调整尺寸或布局，不能偷偷切开。
- 页面标记描述可见源 DOM；ignore 后发生真实重排时，纸张预览才是输出坐标的依据，不再用相减高度伪造源页面坐标。

## 最终验证结果

2026-10-30，当前工作区最终代码：

- TypeScript 检查通过。
- 21 个单元/组件测试套件，85 项测试全部通过。
- CI 模式下使用 2 个 Chromium worker，15 项浏览器自动化测试全部通过（含暗色主题下纸张仍保持白底可读的回归测试），没有触发重试，两次独立复跑分别用时约 1.1 分钟与 1.2 分钟。
- 四个场景均实际下载、解析了 PDF；逐页检查页数、A4 尺寸、页码和正文图像中的非空像素。
- 额外用 `pdfinfo`/`pdftoppm` 对自定义页眉页脚场景的真实下载 PDF 做了一次独立人工复核：2 页、A4 (595×842pt)、jsPDF 4.2.1 生成，页面内容与预览一致，差旅单正文中的住宿/出租车票据以照片形式渲染（非活体表单组件），页眉/页脚与页码按预期跨页重复。
- 库构建和前端生产构建通过；CI 将构建警告视为错误，没有关闭该检查。
- `git diff --check` 通过。
- 依赖审计由 83 项降到 36 项，critical 为 0；剩余 16 low / 6 moderate / 14 high 属于开发/构建工具链。将生产 JS source map 中的 59 个 npm 包名与当前 npm audit 告警对照，匹配项为 0。这是当前锁定依赖下的检查结果，不是“整个项目没有安全风险”的保证。
- 清理了 `PrintSceneItem` 上从未被渲染使用的 `scenario`/`problem` 字段（遗留自早期悬浮说明文案方案，文案已改为仅靠 tab 标题自解释，这两个字段变成死数据）；移除后 TypeScript、单元测试、生产构建、全部 Playwright 用例复跑均保持通过。

依赖审计还没有清零：react-scripts 5 的开发服务器与测试工具链仍有上游告警。本次没有用 `npm audit fix --force` 安装占位的 react-scripts@0.0.0 来伪造零告警，也没有为此迁移框架。部署目标为静态生产构建，不能把开发服务器作为生产服务。

浏览器自动化当前覆盖 Chromium；Firefox/Safari 的完整兼容性不属于本轮已验证结论。当前四场景的功能与异常路径已达到上述明确的验收基线，任意第三方页面、任意 CSS 的完整还原仍受前述渲染能力边界约束。

本次更新 jsPDF 的 peer 最低版本至 4.2.1。下游集成需要同步升级；`createPdfWriter` 为异步初始化，直接使用此底层适配器时需要 await。未执行提交、推送、发布或部署。
